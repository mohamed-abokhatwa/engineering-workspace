Before the pour

The pouring plan is the one date on a construction site that does not move. This holds every pour against the approvals that must exist before it, and warns you while there is still time to chase.

1:53 · WATCHThe concrete date will not wait for your shop drawings
The pour film: the board, the lead you choose, the reasoning behind every match.

The board that watches the dates that cannot slip

Import the pouring plan you already keep — or paste it out of the spreadsheet. Every pour and every watched installation activity is set against the shop drawings and material submittals that must be approved before that date. You choose how many days early you want to be told; from then on the board answers one question, every morning: what is coming, and is the paperwork ready for it.

Import an xlsx pouring plan, or paste the rows straight in — the date column finds itself
You set the lead: flag me 7, 14, 21 days before the pour
States that mean something: ready, watching, at risk, blind — and passed, which is the one you never want to see

How it knows which drawing belongs to which pour

This is the part that is easy to get wrong and dangerous to fake. Location tokens are read from the pour and from the document by the SAME extractor — L21, B2, Zone A, Podium, Roof — so a match is a real overlap of words, not a guess. Then the kind of event decides what counts: a concrete pour needs the drawings that carry the cast obligation, while an installation needs the material submittals for the systems it names. Every row shows the reasoning that produced it, so you can disagree with it.

One extractor reads both sides — the same token means the same thing everywhere
Cast events demand cast drawings; installation events demand the materials for the systems they name
Documents that merely touch the location are shown dimmed and honestly labelled, never counted as cover

Your judgement outranks the matcher — and survives the next import

An engineer who links a drawing to a pour by hand is stating a fact the software cannot infer. That link is kept. Re-import the revised pouring plan next month and the human decisions ride through it untouched; only the dates and the machine matches are recomputed. The same is true of a dismissal: tell it that a pour needs nothing and it stops asking.

Confirm or dismiss any link by hand — it is remembered against the reference, not the row number
Re-importing a revised plan never erases a person's decision
The daily check rings once per date and per missing document — never a second time for the same news

What it reads

The deliverables listShop drawings and their approval state, live.
The registersShop-drawing and submittal registers — which matters, because many projects keep the record there and nowhere else.
Approval states, honestly rankedReturned outranks approved outranks in-review outranks pending — a returned drawing is not cover.
Systems vocabularyChilled water, fire fighting, drainage and the rest, so an installation event knows which submittals belong to it.
